# Как участвовать в разработке MLingo

MLingo сделан так, чтобы банк упражнений можно было расширять без тяжелого frontend toolchain. Основной способ добавления контента — JSON-паки в каталоге `lesson-packs/`.

## Локальный запуск

```bash
docker compose up --build
```

После запуска открой:

```text
http://127.0.0.1:4180/
```

Для полноценного запуска нужен backend с GitHub OAuth. Статический frontend можно открыть через локальный HTTP-сервер для проверки интерфейса и lesson packs, но уроки будут закрыты auth gate до входа через GitHub.

## Где добавлять задания

Новые задания предпочтительно добавлять в отдельный файл:

```text
lesson-packs/<название-пака>.json
```

После этого добавьте файл в `lesson-packs/index.json`. Так приложение сможет:

- загрузить pack при старте;
- синхронизировать pack из GitHub raw URL;
- сохранить его локально для оффлайн-режима.

Встроенные задания в `app.js` лучше менять только тогда, когда нужно поправить базовый набор или сам формат приложения.

## Формат урока

Минимальный урок типа `order`:

```json
{
  "id": "unique-id",
  "kind": "order",
  "difficulty": 2,
  "title": "Название",
  "prompt": "Что нужно сделать?",
  "blocks": ["line_1", "line_2"],
  "answer": ["line_1", "line_2"],
  "hint": "Подсказка без полного решения.",
  "explain": "Почему это важно."
}
```

Поддерживаемые типы:

- `choice` — выбрать один вариант.
- `order` — собрать код из строк.
- `fill` — вписать пропуски.
- `bug` — найти строку с ошибкой.
- `fix` — исправить готовый код.
- `write` — написать решение руками.
- `idea` — написать план решения; локальная проверка идет по rubric keywords.

Подробная схема описана в [docs/lesson-packs.md](docs/lesson-packs.md).

## Требования к хорошему уроку

- Проверяет один конкретный навык.
- Имеет практический смысл для ML-контеста: shape, dtype, leakage, validation, postprocess, loss, metric, threshold, batching.
- Использует только библиотеки из [docs/allowed-libraries.md](docs/allowed-libraries.md).
- Не требует интернета, скачивания весов или внешних pretrained checkpoints.
- Укладывается в короткий игровой блок.
- Дает полезную подсказку, а не общую фразу.
- Имеет объяснение, которое закрепляет идею после ответа.
- Сложность растет от распознавания к ручному написанию кода.

## Сложность

Рекомендуемая шкала:

- `1` — распознать правильный паттерн или базовое понятие.
- `2` — выбрать/упорядочить небольшой фрагмент.
- `3` — написать короткую функцию или исправить типовую ошибку.
- `4` — собрать мини-пайплайн с несколькими контрактами.
- `5` — validation, leakage-sensitive код, ranking metrics, full train/eval loop.

## Словарь терминов

Если урок использует термин вроде `Dice`, `OOF`, `logits`, `GroupKFold`, `NDCG`, `threshold`, проверь запись в `glossary` в `app.js`. Подсказки автоматически подтянут мини-разбор термина.

## Проверки перед PR

```bash
npm test
npm run check
```

Для Android-изменений дополнительно:

```bash
npm run android:debug
npm run android:test
```

`npm test` проверяет синтаксис, Python backend, схему JSON-паков и аудит разрешенных библиотек.

`npm run check` дополнительно собирает Capacitor web bundle и запускает smoke-тест сайта.
